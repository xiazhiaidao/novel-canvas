# 小说画布 · 大一统框架设计稿 v2

> **核心转向：识别基础是地基，轴/视图是地基上的建筑。两者是一体。**
>
> 任何小说项目（不管作者怎么组织文件）都要先被**正确识别**成节点，
> 才能谈坐标、谈轴、谈分享。识别做不好，一切都是空中楼阁——
> 这正是现在画布的现状：很多内容没识别出来，很多被识别错了。

---

## 0. 设计原则

1. **全量可见**：项目里每一个 md 块都必须有归宿——被识别成节点，或进入"未识别池"（灰显可见）。**绝不静默丢弃。**
2. **可解释**：每个节点都知道自己"为什么被这样识别"（哪条规则、哪个层、谁改过）。
3. **可纠正**：任何误识别都能人工改，改完永久生效，重扫不丢。
4. **无题材偏见**：不预设"境界/修为/角色/势力"，类型和轴都由项目数据定义。
5. **无个人硬编码**：代码里不允许出现某个具体书名/文件名/目录名。

## 1. 现状问题：识别缺陷 = 分享障碍（同一件事）

### 1.1 识别漏（内容看不见）

| # | 代码位置 | 问题 |
|---|---|---|
| 1 | `scanChapters` 章节名正则 | 只认 `第X章/序章/楔子/…`，`第1话`、`001.md`、`新生.md`、`chapter 1` 全漏 |
| 2 | `scanChapters` EXCLUDE_DIR | 写死 `白球降临`（个人书名）、`写作参考资料` 等——别人项目同名目录被吞 |
| 3 | `scanDirAsNodes` | 只扫 `设定/角色`、`设定/势力`、`设定/世界观` 三个目录，其他目录的 md 全部不可见 |
| 4 | `parseHeadingSegments` | 只按 `^## ` 切，`###`/`####` 小节被吞进父节点，无法单独成节点 |
| 5 | `parseHeadingSegments` | 无 `##` 的文件 → 整个文件一个节点（可能含几十个章节） |
| 6 | `parseTableSegments` | 只认第一个表头；表格格式稍不规范（无结尾 `|`、单元格不足）全丢 |
| 7 | FILE_DEFS 写死 | `新手域大纲与第五站设计.md` 等个人文件名在代码里，别人没有就静默不扫 |

### 1.2 识别错（内容被分错类）

| # | 例子 | 后果 |
|---|---|---|
| 1 | `大纲.md` 的 `## 卷目标` / `## 剧情主线` | 被当成"大纲节点"混入画布 |
| 2 | `设定.md` 里出现 `## 角色 莫余` 小节 | 被归为 setting 而非 role |
| 3 | 一文件多章节（文件内 `## 第X章`） | 整个文件算一个 volume 节点，章节粒度丢失 |
| 4 | 表格文件（状态追踪/伏笔）列顺序变化 | 按固定列序解析，错位 |

### 1.3 根因

**识别规则写死在代码里，且只覆盖"我这个项目"的约定。** 换个项目、换个人，
规则失效 → 漏 + 错。所以分享障碍的本质 = 识别基础缺失。

## 2. 识别基础（框架主干）—— 一条流水线，四性保证

```
┌────────────────────────────────────────────────────────────┐
│  切分器 (splitting)      md 文件 → 原子块 (blocks)            │
│    · 剥离 front matter    · 按标题层级建树（H1/H2/H3…）        │
│    · 表格块识别           · 正文内章节识别（一文件多章节）       │
├────────────────────────────────────────────────────────────┤
│  分类器 (classification)  原子块 → 节点 {type, chapter, level, lane} │
│    层1 约定规则（config） → 层2 front matter → 层3 AI → 层4 人工   │
│    （优先级：人工 > front matter > 约定 > AI，越具体越优先）      │
├────────────────────────────────────────────────────────────┤
│  校正器 (correction)      误识别 → 人工改 → 持久化             │
│    写入 overrides/classified（按稳定锚点），重扫不丢            │
└────────────────────────────────────────────────────────────┘
               ↓ 产物：节点列表（每个节点带 provenance 来源）
```

### 2.1 切分器（基础之基础）

把 md 变成**带层级结构的原子块**，而不是"整文件"或"拍平 ##"：

```
块 (block) = {
  id:       稳定锚点 (file, startLine) → 重扫不漂移
  file, startLine, endLine,
  heading:  { level: 1|2|3|…, title },   // 标题层级树的一部分
  kind:     "section" | "table" | "frontmatter" | "prose",
  parent:   父块 id（H3 挂在 H2 下）,
  content:  正文（永远留在 md，节点只是指针）
}
```

**切分规则（全部 config 可配，默认值=通用约定）：**
- `#`/`##`/`###`/`####` 全部参与切分（现在只认 `##`）
- 表格块：识别所有表格（不只看第一个），列名可映射
- front matter：剥离，进元数据
- 正文内章节：文件名不匹配章节正则时，**文件内 `## 第X章` 也切分**（一文件多章节支持）
- 无标题纯文本 → prose 块，进"未识别池"

### 2.2 分类器（四层递进，越具体越优先）

| 层 | 机制 | 优先级 | 说明 |
|---|---|---|---|
| 层4 | **人工纠正** | ★★★★ | 用户手动改的 type/chapter/level/lane，永久生效 |
| 层2 | **front matter** | ★★★ | 作者显式声明，最高自动优先级 |
| 层1 | **约定规则** | ★★ | config.scan（files/dirs/chapters 映射），无 config 用内置默认 |
| 层3 | **AI 兜底** | ★ | 批量分类未识别块（v2） |

**关键：四层产生同一份输出** `{type, chapter, level, lane}`，管线统一，只是来源不同。
分类结果 ≠ 写回 md，存布局文件（§5）。

### 2.3 四性保证（识别基础的质量标准）

**① 全量可见**
- 切分后每个块必须落入：已识别节点 **或** 未识别池
- 未识别池 = 画布上一组灰显节点（可整体展开/收拢），侧边栏文件树同步标注"未识别"
- **不存在的操作：静默丢弃**

**② 可解释（provenance）**
```
每个节点记录来源：
  recognizedBy: "config:files:设定.md" | "frontmatter" | "ai" | "manual" | "unrecognized"
节点悬停提示：来自 设定.md ## 莫余 (行 5-30)，规则: config.files[设定.md] heading
```

**③ 可纠正**
- 任何节点：改 type / 改标题 / 合并 / 拆分 / 移到别的父块
- 操作写入 `overrides`（按 (file,startLine) 锚点），下次扫描照样生效
- 未识别池里的块：一键"标记为角色/章节/…" → 立即成为节点

**④ 可复现**
- 同一项目 + 同一 config + 同一 overrides → 识别结果 100% 相同（确定性）
- AI 层结果**缓存**（classified），人工确认后才算数，AI 不隐形改数据

### 2.4 识别报告（质量反馈）

打开项目时生成一份报告，用户一眼看到问题：

```
识别报告：
  ✓ 已识别 342 个节点（章节 218 / 角色 24 / 设定 56 / 大纲 44）
  ⚠ 未识别 12 个块 → [查看]
  ⚠ 可疑 5 处：
    · 正文/第1卷.md 整文件单节点（可能含多章节，未按 ## 切）→ [切分]
    · 追踪/状态追踪.md 有表格未解析 → [解析]
    · 大纲.md 的 "## 卷目标" 被识别为大纲节点（可能是模板）→ [改类型]
```

可疑清单 = 规则引擎对"可能是错的"的主动标注（整文件单节点、表格存在但未用 table 模式、标题含"模板/说明"等）。

## 3. 通用节点模型（识别产物）

```jsonc
{
  "id": "chapter:正文:第一卷:第01章:第1章-xxx",   // 稳定锚点 (file, startLine)
  "title": "第1章-xxx",
  "type": "chapter",
  "label": "章节",
  "source": { "file": "正文/第一卷/第01章.md", "startLine": 1, "endLine": 120 },
  "parent": null,                              // 层级树（H3 挂在 H2 下）
  "chapter": 12,                               // X：章号
  "level": 2,                                  // Y：轴层级序号
  "lane": "主角线",                             // 泳道色
  "recognizedBy": "config:files:…",            // 来源（§2.3 ②）
  "desc": "……"
}
```

## 4. 轴与视图（识别产物的下游消费）

**轴是识别之后的第二件事**——只有节点被正确识别（type/chapter），轴才有东西可画。

### 4.1 轴定义（项目级，无题材偏见）

```jsonc
"axis": {
  "name": "进度",                      // 轴名
  "levels": ["开端", "发展", "高潮", "结局"],   // 作者定义，无默认境界
  "unknownLevel": "未分类"
}
```

| 预设 | 说明 | 默认？ |
|---|---|---|
| 四段式 | 开端→发展→高潮→结局 | ★ 默认（所有体裁通用） |
| 卷 | 按目录自动生成 | 可选 |
| 大纲里程碑 | 按大纲自动生成 | 可选 |
| 境界 | 炼气→筑基→… | 可选模板，仅玄幻，**非默认** |
| 自定义 | 言情：初遇→暧昧→确立→波折→HE；历史：势力/时代… | 任意 |

### 4.2 视图模式

| 模式 | 说明 | 坐标来源 |
|---|---|---|
| `free`（现有） | 自由拖拽画布 | `nodes[id].{x,y}` |
| `axis`（新增） | 网格+刻度+泳道；X=章号、Y=层级序号 | `nodes[id].{chapter,level,lane}` 投影 |

- 未识别/未分类节点 → 轴视图"未分类"行灰显，不报错
- 切换视图 = 换投影函数，零数据复制

## 5. 存储格式

```
我的小说/
├── 正文/ 设定/ …                    # 纯 md，原样
├── novel-canvas.config.json         # 规则 + 轴定义（作者/分享者维护）
└── 小说画布.json                    # 状态：坐标 + 连线 + overrides + classified
```

```jsonc
// 小说画布.json（状态层）
{
  "version": 3,
  "mode": "free" | "axis",
  "nodes": { "id": { "x": 120, "y": 40 } },
  "customLinks": [["a", "b"]],
  "overrides": {                       // ★ 人工纠正（§2.3 ③），按锚点持久
    "设定.md#12": { "type": "role", "title": "莫余" }
  },
  "classified": {                      // AI 结果缓存（§2.3 ④）
    "设定.md#40": { "type": "faction", "level": 1 }
  },
  "unrecognized": ["设定/地图.md#1", …]   // 未识别池（§2.3 ①）
}
```

**向后兼容：** 旧项目无 config/无 overrides → 回退现有行为，原样能开。

**v1 验证记录（2025）：**
- 影子模式 diff：旧 59 节点 id 全部保留（0 缺失、0 字段不一致），新增 61 节点全部 `unrec:` 前缀。

**v1.1 反馈修订（2025）：**
- **Y 轴方向**：开端在底部、结局在顶部、未分类悬顶（进度自下而上）。
- **轴视图交互**：空白拖拽平移 + 滚轮缩放（此前锁死视角），节点拖拽反算已修（章号四舍五入偏移 +0.5）。
- **识别报告闭环**：可疑识别条目可改类型保存；未识别提升后同步内存 overrides 并整表刷新；底部显示已保存计数 + 「让 AI 分析未识别内容」一键入对话。修复人工提升后节点仍滞留未识别池的 bug（override 生效时清 `unrecognized` 标记）。
- **默认识别增强**：默认 dirs 规则扩展（设定/角色/势力/世界观/大纲/伏笔/上下文 目录级匹配，更具体规则优先去重）；新增 `ignoreUnrecognized` 排除工具/说明类文件（CLAUDE.md、安装/效果/README 等）。默认项目未识别文件 4 → 1（卷纲→大纲、工具文件不再入池），未识别节点 61 → 26。
- **agent 消费识别结果**：`get_context` 追加未识别内容摘要；`list_nodes` 支持「未识别」过滤并返回 `unrecognizedCount`，AI 可协助归类。

**v1.2 轴视图布局修订（2025）：**
- **不再堆叠**：未分章节点按文件+行号排序后 round-robin 铺到各章列；未分类节点在带内 **2 并排网格** 堆叠（列宽 ≥340 时），纵向步进紧凑 —— 默认项目 81 节点从"全部叠一个点"变成 3 章列 × 2 并排的整齐网格（实测仅 1 处重叠）。
- **轴更大**：列宽 340 / 行高 100，fit 时内容填满视口（scale 0.2~1.6，不再锁 1）；章少（≤4）用固定宽列，章多响应式收缩。
- **修复 transform 污染裁剪框**：平移/缩放 transform 改施加在 `#axisInner` 内容包装层，`#axisView` 保持 `inset:0` 固定裁剪 —— 之前 transform 直接挂在视口元素上，导致可见区被缩放/位移（实际只露出 320×296 的窗口，大量卡片被裁掉）。
- **修复 fit 居中负坐标**：未分类带顶为负坐标（bandTop = axisPadT − bandH），fit 居中需减去 topCoord×scale；内容高度去掉重复计入的 axisPadT。
- **轴内紧凑卡片**：宽 150 / 最小高 24，隐藏 ndesc 与 nmeta（只显类型标签+标题），重叠 137 → 1。
- **修复 X 章号标签定位**：容器改为定位到层级区下方（不再 bottom:0），标签顶对齐。

**v1.3 轴视图"从起点铺满"修订（2025）：**
- **未分类节点不再全堆顶部带**：改为 round-robin 均匀铺到各层级行（从开端开始）—— 默认项目 81 节点：开端 21 / 发展 21 / 高潮 21 / 结局 18，整根轴从起点到终点全部铺满（此前全部挤在"结局"上方的未分类带）。灰色仍表示未分类，提示条注明"灰色=未分类(暂铺在层级行)"。
- **行高自适应**：每层级行高度随格内卡片数增长（最小 100，深度×34 步进），层级标签定位到各自行中心；未分类带只在"无层级定义"时作为溢出容器出现（bandH=0 时隐藏"未分类"标签）。
- **更紧凑**：列宽 340 → 280、卡片 150 → 130（2 并排 130×2+20 = 列宽），重叠 1 → 0，scale 0.514 → 0.604。
- **拖拽反算适配动态行高**：`axisLevelFromY` 按 rowTopY/rowH 区间反查层级，不再用固定行高公式。

**v1.4 横向章节轴修订（2025）：**
- **章节沿 X 轴铺开，不叠 Y 轴**：改为「Y = 固定层级泳道（开端底→结局顶，行高 100）+ X = 章列」布局。卡片在 (章, 层级) 格内**横向 lane 展开**（沿 X 轴铺开，步进 138px），不再纵向深堆叠 —— 之前每格 2 并排 × 4 层深的"叠 Y 轴"问题消除。
- **读取真实章数自适应**：`maxChapter` 读节点真实章号（列车求生 82 章、房车求生 27 章自动铺 82/27 列）；每章列宽随该章卡片数自适应（第3章 13 张卡 → 列宽 1814px，普通章 1 张 → 280px）。列宽不随章数收缩到 180。
- **fit 不再硬缩全图**：章少时按宽度全图 fit（scale 更大），章多时**宽度保底 0.55**（卡片保持 ~72px 可读），X 方向横向平移浏览 —— 之前 77 章项目被压到 scale 0.2、卡片 26px 不可见（"轴太小"根源）。
- 实测：3 章项目 81 卡横向铺 3200px、0 重叠；82 章项目 133 卡横向铺 25000px、bh 固定 460（不再纵向堆叠）。

## 10. 迭代记录（v1.8 剧情推进轴）

### v1.8 Y 轴升级：4 条离散泳道 → 连续剧情推进轴（形似 y=x）
**用户反馈**：「章节分布不对，y 轴太简陋了，章节在 xy 轴上应该形似 y=x——随着章节推进剧情即 y 值也会增加」

- **Y = 连续剧情推进 0~100%**：不再分 4 条泳道。默认每章 `progress = (章号-1)/(最大章-1)*100` —— 第 1 章贴底（开端 0%）、第 N 章到顶（结局 100%），全图就是一条 y=x 对角线
- **层级降级为参考网格线**：开端/发展/高潮/结局 变为虚线参考线 + 百分比刻度（`开端 0%` 底部 → `结局 100%` 顶部），不再决定卡片位置
- **y=x 对角线引导线**：从 (第1章, 开端) 到 (第N章, 结局) 的虚线引导（CSS dotted），一眼看出"剧情随章节抬升"
- **plotH 600px**（6 行高）：80+ 章长篇小说对角线也清晰可见
- **拖节点上下 = 调该章剧情推进**：`axisProgress[章号] = 0~100` 覆盖默认对角线；同章多卡片共享同一推进 y，横向 lane 展开不重叠
- **拖节点左右 = 改章号**（不变）；拖到顶部未分类带 = 清章号
- **详情面板**：原「层级」下拉换成「剧情推进(0-100)」数字输入，空 = 自动 y=x，填数 = 覆盖该章
- **持久化**：布局文件新增 `axisProgress`（章号 → 0~100），与 `axis`/`overrides` 并列，`version: 3` 不变
- **顺手修复两个存量 bug**：
  1. 类型下拉缺 `volume`/`chapter` → 章节节点保存属性会被静默改成「角色」（默认选中第一项）；已补全选项与 TYPE_LABEL_MAP
  2. 保存属性且类型变更时，`loadData()` 会用旧布局文件清掉内存里刚写入的 `axisProgress`（旧 bug 对 `layoutAxis` 同样存在）→ 拆出 `postLayout()` 立即落盘后再重载
- 冒烟测试 72 项全绿；列车求生 82 章对角线实测：ch1(160,623) → ch10(3178,557)，逐章上移 4~8px，符合 y=x

### v1.8.1 统一算法修正：最后一章不再钉死"结局" + Y 轴细化
**用户反馈**：「怎么就 3 章就到结局了，y 轴要细化，其他项目怎么没有？要做统一算法适配别人的项目，不是单独项目适配」

- **默认推进公式修正**：`(章号-1)/(最大章-1)*100` → `(章号-1)/最大章*100`
  - 旧算法把**最后一章强制钉在 100%（结局）**——对 82 章的完本小说合理，但对只有 3 章的在写项目（天灾生活）第 3 章直接顶到"结局"，明显错误
  - 新算法统一成立：任何规模项目最后一章**接近但不到 100%**——3 章项目 ch3=67%（高潮）、27 章项目 ch27=96%、82 章项目 ch82=99%
  - 章节越多越贴顶（接近完本），章节越少越靠下（在写/未完结）——**同一公式自动适配，无项目特调分支**
- **Y 轴细化**：新增每 10% 一条淡点线细网格 + 左侧 9px 小百分比标签（10%~90%，跳过层级位置避免重叠）；层级线（开端 0% / 发展 33% / 高潮 67% / 结局 100%）保留为粗虚线
- **实测三项目统一生效**：天灾 3 章 0/33/67、房车 27 章 0→96 完美单调对角、列车 82 章 0→99
- **视图一致性**：房车求生布局 mode 设为 axis（进度轴视图对所有有章节项目统一可用）；修仙小说 0 章全部进未分类带（正确兜底，不做项目特调）

## 11. 迭代记录（v1.9 Y 轴分段：卷 / 境界 / 剧情关键节点）

### v1.9 需求
**用户反馈**：「y轴太广了，细分y轴，按第一卷第二卷来，如果小说项目没有这个就询问作者按境界还是剧情关键节点来」

三件事：
1. Y 轴从一条连续的 0-100% 轴线，细分为**若干个横向分段（band）**
2. 分段**优先按卷**：第一卷在底部、第二卷在上……章节按所在卷归入对应带，带内按章号均匀铺开（每卷一条迷你斜线 → 整体阶梯状）
3. **项目没有卷结构时，进入进度轴视图会询问作者**：按境界（练气/筑基/金丹……）还是按剧情关键节点（开篇/转折/高潮/结局……），并让作者填分段名称；也可选"按剧情进度"保持连续轴

### 实现要点

**分段解析（统一算法，任何项目生效，无项目特调）**
- `volumeFromPath(n)`：从章节文件路径自下而上找第一个含"卷"的目录（支持 `第一卷/001.md`、`第一卷·新手域/01.md`、`正文/第一卷/第01章.md` 等任何别人项目的目录习惯）
- `detectVolumeBands()`：聚合所有章节所在卷目录，按"第X卷"数字排序（中文数字一~十也支持）
- `resolveAxisBands()`：优先级 = 显式选择（realm/plot/progress，持久化在布局） > 卷自动检测 > null（需要询问）
- 分段不改变 Y 的 0-100% 连续几何：`yForProgress/progressFromY` 原样复用，band 只是等分切片（第 i 带 = i/N ~ (i+1)/N）

**带内推进（形似 y=x 的阶梯版）**
- 卷模式：章节 progress = `(卷序号 + 带内 rank/该卷章数) / 卷数 × 100` —— 每卷首章在带底、末章≈带顶、末卷末章也不到 100%（与 v1.8.1 的"最后一章不钉死结局"原则一致）
- 境界/剧情节点模式：按章号比例分布（默认对角线），作者之后可拖节点上下微调（落盘 axisProgress 覆盖）
- axisProgress 显式覆盖永远优先于分段默认

**询问弹窗（axisYModal）**
- 触发条件：进入进度轴视图时 `resolveAxisBands()` 为 null（无卷 + 无持久化选择）+ 项目有章节
- 选项：按境界 / 按剧情关键节点 / 按进度（不分区保持连续轴）；分段名称每行一个、自下而上
- 底部工具条（axisBar）新增：`Y:按卷 / 按境界 / 按关键节点 / 按进度` 下拉随时切换，`分区` 按钮修改名称

**渲染**
- 分段模式：band 分界线（accent 虚线）+ 带名标签（`第一卷 0~33%`），保留 10% 细刻度点线；不再画层级线/对角线（分段就是结构）
- 无分段模式：维持 v1.8.1 的层级线 + 10% 细刻度 + y=x 对角线

**持久化**
- 布局新增 `axisBandMode`（volume 不持久化=自动 / realm / plot / progress）与 `axisBands`（分段名数组）
- server `/api/data` 返回、`/api/layout` 保存均支持；`''` 清空可正确落盘（merge 用 `!== undefined` 判断）
- 冒烟测试：前置守卫与进度轴检查中加入关闭询问弹窗的兜底（测试项目无卷时避免遮挡点击）

- 天灾（3 章 1 卷）、房车（33 章 1 卷）：单卷带，带内 (rank-1)/count 与 v1.8.1 公式一致
