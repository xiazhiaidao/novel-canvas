# 角色状态追踪与变更记录 · v1.32.0

原实现只展示角色卡数量、首条要点和最后名字命中的章节。身份可能被误当成状态，强调键与表格漏解析，缺字段的卡片会从统计中消失，也没有状态变动明细。本轮把状态字段、正文线索、磁盘卡片变化和 Agent 核对连接起来，无新增依赖。

## 使用方式

1. 打开“分析 → 角色追踪”，或选中角色，从详情的“角色状态追踪”进入。监控的角色卡、状态看板和全书统计也可直接打开。
2. 搜索姓名、声明的别名或状态。筛选“待核对”“缺少当前状态”“有变更记录”。左侧选人物，右侧查看当前状态字段、来源、状态截至章号和待核对项。
3. 展开正文线索，查看命中的章节、别名、文件、行号和片段，点击跳到画布章节。名字/别名命中可能来自回忆或他人提及，不能直接判定人物实际出场或状态变化。
4. 点击“编辑卡片”修改原文，或“核对并更新”新建人物 Agent 任务。新任务保留旧任务要求，引用人物卡和最近章节线索，支持当前未保存草稿，不自动发送。
5. 发送后由 Agent 查阅章节，核对状态与截至章节，生成待审提案。查看差异、接受后才写回文件。页面刷新统计、字段和变化记录；任务可“返回角色”。

## 建议的角色卡格式

```markdown
## 林舟
- 身份：主角
- 别名：云客、林公子
- 当前状态：持钥匙守住木门
- 当前位置：南门
- 境界：二阶
- 伤势：左臂轻伤
- 当前目标：阻止守卫夺走钥匙
- 关系：与沈青暂时结盟
- 持有物：旧钥匙
- 状态更新章：第35章
```

普通键值、强调键、两列表格及 `### 当前状态` 小节均可解析。默认追踪文件也可用含“角色/姓名”列的横向人物表，无需更改扫描配置；已有可解析人物分节时优先保留分节，避免把关系表替换成人物卡。自定义扫描规则仍支持 `table: true`。

更新章号只从明确的更新字段读取，不以最后名字出现的章节代替。未填写状态、未记录更新章号、卡片截至章号落后于正文线索、长期无字面提及、没有匹配正文等均列为待核对。它们是核对入口，不是自动判定剧情矛盾。

## 变化记录的含义

- 首次扫描只建立字段基线，不补造此前历史。
- 两次磁盘扫描之间字段变化后，保存检测时间和每个字段的前后值，每张卡片保留最近 100 次变化。检测时间不是剧情发生时间；截至章节来自卡片声明。
- 编辑保存、提案采纳及 60 秒监控轮询会刷新。仅改变正文不会自动改变角色状态，需要作者或 Agent 核对后更新人物卡。两次扫描之间的中间版本无法恢复。
- 未保存草稿、未接受提案不进入历史；重复刷新不重复记账。字段改名会表现为旧字段清空和新字段增加。
- 记录跟随项目内节点 ID。人物重命名、删除再添加或扫描规则变更可能建立新基线，不合并不同卡片的历史。
- 浏览器服务默认存于应用 `.data/character-history/`；桌面应用通过 `app.getPath('userData')/character-history/` 保存，避免写入打包后的只读源码。文件名使用小说绝对路径的 SHA-256，项目同名也不会串记录。
- 存储失败时显示错误提示，不修改小说 Markdown。迁移应用数据目录时需同时迁移这些 JSON 文件；这份记录不是小说备份，原有 `.bak` 和快照机制仍负责备份。
