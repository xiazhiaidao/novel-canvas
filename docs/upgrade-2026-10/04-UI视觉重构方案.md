# 小说画布 UI 视觉重构方案

日期：2026-10-04。最初针对 1.26.0 提出。用户确认浅色图片方向后，已在 1.27.0 落地实际界面；配套 HTML 保留为原设计提案。

实现采用固定顶部章节尺、左侧纵向分区尺；保留卷、境界、剧情阶段、进度及可选剧情泳道。图片中的人物/伏笔分类不转为 Y 轴分区。实际节点摘要、章号和字数来自项目数据。

## 设计判断

上一轮解决的是 AI 工作流程，视觉仍沿用多轮叠加的旧样式。现有截图与 CSS 的主要问题：

- 深色底面上大量米白实心按钮成为视觉中心，正文和回复反而退到后面。
- 多处文字只有 10.5–12.5px，标题、正文、路径、状态的尺寸相近，依赖加粗和彩色标签区分。
- 侧栏、工具栏、标签、卡片叠加圆角、边框、渐变、发光和阴影，缺少统一的控件等级。
- 画布全图缩放后节点过小，卡片内容不可读；长提示、图例、轴控制和导航同时留在界面上。
- AI 任务和目标在顶部，参考资料在底部，发送按钮另占一块；回复区域被操作面板分割。
- 深色样式后面又叠加多个按钮覆盖与 force-black 规则，单靠增加新 CSS 会继续制造冲突。

## 推荐方向：清晰、安静的写作桌面

以冷灰纸面、墨蓝强调色和清晰中文排版建立气质。真正的主角是正文和情节，不是按钮。视觉记忆点是“章节横向展开、情节纵向对照”的稿件结构：章节号与章名成为画布的可读坐标，主线、支线、人物和伏笔各有明确位置。

不用仿纸纹理、复古装饰、玻璃效果或彩色发光。编辑器正文可用宋体；界面标签与 AI 建议使用现代中文无衬线。

### 基础规格

| 项目 | 浅色 | 深色 / 行为 |
| --- | --- | --- |
| 工作区底色 | `#EEF1F3` | `#181D23` |
| 面板 / 卡片 | `#FFFFFF` | `#20262D` |
| 主文字 | `#242C34` | `#E7EBEF` |
| 次文字 | `#64717D` | `#A3AFBB` |
| 分隔线 | `#DEE4E8` | `#353F49` |
| 强调色 | `#315C72` | `#9CC4D5`；主按钮背景另配高对比文字 |
| UI 字体 | Microsoft YaHei UI / PingFang SC / sans-serif | 13–14px，标题 16–18px |
| 正文字体 | 用户可选：宋体 / 微软雅黑 | 默认 18px、行高 1.95、阅读列 640–760px |
| AI 回复 | UI 字体，14–15px | 行高 1.75–1.85，段落间距 12px |
| 控件尺寸 | 常规高度 32px，命中区域至少 32px | 面板标题 44px，主顶栏 52px |
| 圆角 | 控件 6px、卡片 10px、浮层 12px | 不再混用大量胶囊 |
| 阴影 | 常驻面板无阴影 | 仅菜单、提案浮层、拖动卡片使用 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px | 通常 16px 面板边距、24px 内容边距 |

当前 CSS 里的“强调文字统一黑色”历史规则需要收敛为浅色主题的文字规范。深色强调文字和主按钮文字按背景匹配；不把黑字强行放到深色底面上。主题强调色仍通过令牌配置，墨蓝只是推荐默认值。

## 界面结构

```text
顶栏：小说画布  /  当前小说         画布 · 正文          搜索  主题  AI
┌──────────────┬─────────────────────────────────┬───────────────────┐
│ 当前小说     │ 当前位置 / 工作区工具            │ AI 助手           │
│              │                                 │                   │
│ 内容导航     │ 画布：章节 × 情节线              │ 问题与建议        │
│ 卷 / 章      │ 或正文：居中、可读的正文列        │ 紧凑提案卡片      │
│              │                                 │                   │
│ 人物与设定   │                                 │ 参考资料 · N      │
│ 伏笔         │                                 │ 任务 / 目标       │
│ 检查与工具   │                                 │ 输入框 + 发送     │
└──────────────┴─────────────────────────────────┴───────────────────┘
状态栏：保存状态 / 字数；次要技术信息按需展开
```

1. 顶栏分成小说位置、工作区切换和全局操作。识别、图例、关系筛选放入画布工具；生成、润色、检查放入写作菜单，不再同排竞争。
2. 左侧导航默认 216px，可调 192–280px。卷章结构直接可见；人物、设定、伏笔和工具使用清晰分组。移除活动栏和侧栏标题中的重复导航。功能数量不减少，降低默认展开量。
3. 右侧 AI 默认 360–400px，可调到 520px；AI / 详情使用同一插槽。长回复可展开为主工作区。视口小于 1180px 时默认收起左栏，低于 980px 时 AI 为抽屉，正文不被压成窄条。
4. 模型名称、文件完整路径、连接信息和停靠选项只在对应菜单显示。底栏保留保存状态和字数，减少技术标签。

## 分区改法

### 画布

- 常用操作只留“新增节点、视图切换、关系”；全图、缩放、小地图集中在右下角。
- 章节号与章名组成固定顶部坐标，情节线标签位于左侧。节点内容区保持拖动和缩放，坐标与内容变换分开处理。
- 正常工作缩放下卡片建议宽 220–260px：类型小标、标题、两行摘要、章节 / 状态。省略文件路径，点击后再看完整内容。
- 类别颜色只用于小点或细标记，卡片本身保持同一底色。连线不使用发光；只高亮选中节点相关关系。
- 全图模式明确作为总览，简化卡片显示；双击卡片或“定位”恢复可读缩放，不承诺任何缩放下都能读全文。
- 长操作说明移到帮助菜单，空白界面使用一句引导。默认界面不覆盖提示条。

### 正文编辑器

- 中间是一列可写正文，标题、正文、字数建立明确层级。宋体只作用于正文，标题也可使用 UI 字体。
- 可编辑缓冲区仍维护 Markdown 真源。采用现有 textarea 时先优化文字、宽度与滚动，不把静态排版示意冒充富文本实现。
- 保存靠近文件标题；自动保存只有真实实现后才显示。未保存状态以小点和文字表示。
- 删除、重命名、路径放入文件菜单。选中文字时提供“加入 AI / 润色 / 改写”；键盘用户可从固定工具菜单使用同样动作。
- AI 味检测、人物推进等结果放入右侧检查页或独立抽屉，避免在正文下堆叠多个大型卡片。
- 专注模式收起左栏、AI 与底部次要信息；仍保留保存状态和退出入口。

### AI 对话

- 标题只显示“AI 助手”和展开 / 更多。任务与目标放到输入区附近，发送前能确认。
- 顶部提供本轮主题的简短标题；多会话管理是后续独立需求，本轮视觉重构不假装已支持。
- 用户要求使用低对比小块；AI 回复直接排版，不给每段正文套完整聊天气泡。
- “参考资料 · N”默认折叠为一行，可打开查看完整列表、内容及实际截断状态。异常截断提示保留，不以美观为由隐藏。
- 输入区统一包住任务、目标、修改开关、引用与发送。提示文字具体，例如“让周砚的选择更难，但保留他的动机”。
- 每条回复的复制、引用按钮在悬停与键盘聚焦时显示；主要操作“查看修改”一直显示。
- 提案卡显示标题、目标文件和状态，详细差异进入审阅页。接受成功后显示已写入；拒绝、冲突与未保存草稿有独立状态。

### 提案审阅

- 宽屏支持原文 / 建议并排，窄屏上下排列。变更用低饱和背景、小标记与文字区分，不依赖红绿颜色。
- 顶部显示文件与修改目的，底部固定“保留原文 / 继续调整 / 接受修改”。
- 实际变更区间与全文比较沿用现有逻辑，不为美化引入虚假逐行差异。原型展示的是视觉排版。
- 接受后回到文件并更新卡片；等待时有明确状态，继续输入的草稿保留。

## 实施顺序

| 阶段 | 改动 | 验收重点 |
| --- | --- | --- |
| 第一批：视觉底座 | 清理重复主题覆盖；统一颜色、文字、按钮、图标、边框与间距 | 浅深色可读；不再出现深底白色按钮墙；键盘焦点完整 |
| 第二批：工作区 | 顶栏减项、左栏分组、正文排版、右侧宽度与 AI 输入区整合 | 1440px 与 1280px 正文可读；收起面板后状态不丢 |
| 第三批：画布与审阅 | 可读卡片、章节坐标、工具合并、差异页统一 | 拖动、缩放、连线、节点定位、提案接受及草稿保护仍正常 |

落地以现有原生 JS/CSS 为基础，不换框架、不加图标库。图标使用统一 18px SVG、1.5px 描边。不要继续在 `canvas_theme.css` 末尾追加互相抵消的样式；将重复定义迁移到组件基础样式与主题变量，分批删除旧覆盖，每批检查视觉和交互。

验收视口建议 1600×1000、1440×900、1280×800、980×760；同时检查系统 125% 缩放、长书名、长路径、空画布、长回复、错误状态、未保存正文、提案冲突。浏览器原型不能替代 Electron 上的实际检查。

## 配套原型

`ui-redesign-preview.html` 为无依赖、可离线打开的方向原型。可切换画布 / 正文、浅深色、AI 面板、参考资料与提案审阅。使用虚构小说“雾港来信”示例。它不连接模型、不读写小说、不实现真实保存或接受；演示按钮均明确标为原型行为。

原型已检查 1600×1000、1440×900、1280×800 与 980×760 的布局；资料展开后输入区仍在视口内，AI 展开与收起、提案审阅和调整回填已检查。附画布浅色、正文浅深色与审阅深色截图。此结果只验证原型，不代表运行版已完成改造。
