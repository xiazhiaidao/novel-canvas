# 1.34.0：收尾进度、审阅恢复与撤销、时间线同步

本轮承接 1.33.0 的本章收尾与逐段采纳，补齐处理结果和恢复路径。

## 使用入口

- 创建本章收尾后，任务清单默认展开人物、伏笔、摘要、时间线的单独进度。修改提案旁可纠正收尾归属；无需修改时点击“确认已核对”，记录依据。部分采纳或拒绝不会自动判定本项完成。
- 逐段勾选及手动编辑即时保存到浏览器存储；刷新后打开原待审提案恢复。采纳和拒绝后清理该审阅草稿。
- 已采纳的任务卡片可以“撤销采纳”；文件的“写作工具”也可撤销最近一次采纳。未保存草稿或磁盘后续修改会阻止直接撤销。撤销后不自动恢复原提案。
- 已采纳/已撤销的收尾时间线卡片可打开同步预览；任意 Markdown 文件也可从“写作工具 → 同步到时间线”进入。勾选所需新增、更新或删除，再点“同步所选”。

## 数据与边界

Markdown 仍为小说数据真源。收尾任务保留生成时的正文依据；正文改变后提示旧收尾需要重新核对，不自动覆盖原任务。任务整体显示“收尾完成”需所有选中的项目已采纳或有作者核对记录。

时间线解析不调用模型，也不推断日期。支持明确“第N章”标题下的事件列表/简短段落，及包含“章节、事件、时间、依据”的表格。建议增加唯一的“事件ID”列：改名称或所属章号仍更新同一画布节点；无 ID 时按章节内顺序匹配，重排事件时需仔细核对预览。

同步仅修改视图层的 `timelineNodes`，保留手动节点、现有推进值及布局版本 3。删除默认不勾选；预览后 Markdown 或画布改变会阻止旧方案写入。撤销 Markdown 不自动撤销之前的画布同步，可重新预览确认更新/删除。

采纳历史记录整份原文件与采纳结果哈希，用于精确撤销。源码/目录版仍使用 `.data`；asar 桌面包在 Electron 用户目录的 `service-data` 保存服务数据，环境变量 `NOVEL_CANVAS_DATA_DIR` 可指定位置。历史提案 ID 保留，新提案使用 UUID，防止重启后编号复用误关联旧任务。

- 实际刷新验证审阅恢复；实际服务重启验证待审提案与撤销记录恢复。覆盖未保存草稿、后续磁盘修改、跨项目操作、时间线重复同步及预览后的文件/布局变化。
- 浅色、深色及 480px 窄窗口已检查，截图保存在同目录 `screenshots/closure-*.png`。
