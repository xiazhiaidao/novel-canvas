# 右侧栏升级方案（职责修订版）

日期：2026-10-05。范围：Novel Canvas 1.28 的右侧节点面板与中下区域 Agent 助手。

本方案已在 1.29.0 实施。此版本替代此前“右栏同时提供写作助手 / 节点详情”的推荐布局，依据用户指出的中下区域 Agent 入口，重新划分职责。已有停靠偏好保留，没有设置过偏好的用户默认底部停靠。节点草稿在当前窗口内按项目保留，尚未加入关闭应用后的持久化恢复。

## 1. 先明确：全应用只有一个 Agent 工作区

当前代码只有一个 `#chatPanel`。`app.js` 中的 `syncChatPanel()` 根据停靠位置把它移动到中下区域、右侧、左侧或悬浮层，并不是两套独立助手。

此前方案没有讲清楚这一点。若保留中下区域的 Agent，同时在右栏新增独立聊天页，就会重复任务历史、输入框、资料管理和执行状态，应取消这一设计。

推荐默认布局：中下区域保留唯一 Agent 工作区，右侧改为所选节点的内容与属性面板。允许用户把同一个 Agent 面板移动到右侧；移动后中下区域不再显示 Agent，右侧临时显示 Agent，节点详情通过切换恢复。

## 2. 推荐职责划分

| 区域 | 核心职责 | 可见内容 |
| --- | --- | --- |
| 中央上方 | 浏览、组织与写作 | 画布 / 正文 / 差异审阅 |
| 中央下方 | 唯一 Agent 工作区 | 要求输入、任务历史、引用资料、执行过程、回复、待审修改 |
| 右侧栏 | 所选节点检查与编辑 | 节点内容、来源、类型、章号、剧情推进、泳道 |

右栏保留“添加到 Agent”入口，点击只把节点或片段加入现有 Agent 引用并展开该工作区，不另开聊天、不自动发送。

## 3. 默认布局示意

┌──────────┬────────────────────────┬───────────────────┐
│          │                        │ 节点详情           │
│          │     画布 / 正文         │                   │
│ 内容导航 │                        │ 第02章 第二次敲门  │
│          │                        │ 章节 · 238 字      │
│          │                        │                   │
│          │                        │ 内容   属性        │
│          │                        │                   │
│          ├────────────────────────┤ 完整内容预览……    │
│          │ 写作 Agent  任务名  ⋯  │                   │
│          │ 执行过程 / 回复 / 修改 │                   │
│          │ 引用资料               │                   │
│          │ 输入要求            ↑ │ 添加到Agent  编辑  │
└──────────┴────────────────────────┴───────────────────┘

## 4. 右侧栏升级重点

1. **内容优先**：标题下面放类型、字数和来源短名，默认展示内容预览；完整路径和行号放进来源详情。
2. **属性分开**：采用“内容 / 属性”两个子页签。属性页保留类型、章号、推进和泳道，避免表单挤占阅读区域。
3. **操作收敛**：保留“添加到 Agent”“编辑内容”；复制节点 ID、AI 味检测等次要操作进入更多菜单。
4. **编辑明确**：进入编辑后显示未保存状态及“保存内容”。“保存属性”留在属性页，两种保存保持明确的写入目标。
5. **简化空白态**：未选节点时显示“选择画布节点查看内容”，不摆放聊天示例或 Agent 输入框。
6. **状态保留**：切到 Agent、折叠右栏、切换停靠位置不能丢失节点草稿；切换另一节点前明确处理旧节点未保存内容。

右侧宽度建议默认 340–360px，允许在 300–480px 内调整；窄窗口使用抽屉，避免把中央画布和正文压得过窄。

## 5. 中下区域 Agent 同步优化

其功能保持集中，改善布局即可，不再把功能搬散到右栏。

- 默认高度建议 260–320px，可拖动、折叠；收起后显示约 40px 的任务标题栏。
- 标题栏放当前任务、运行状态、新建、历史和更多，避免重复“Agent 标题 + 相同任务标题”信息。
- 对话、执行过程和修改清单共用一个主滚动区域，输入固定底部。
- 参考资料统一成一个展开入口，引用标签靠近输入；模型与模式在紧凑工具行中展示。
- 待审修改改成单层文件列表，突出“查看差异”；查看差异沿用中央审阅工作区。
- 宽屏底部布局中，消息与输入内容建议限制到约 880px 并居中，避免回复一行过长。
- 长回复提供展开到主工作区的入口；收起或还原后保留滚动位置和输入草稿。
- 完成后折叠执行过程；失败、已停止、待继续保留明确文字状态。

## 6. Agent 移到右侧时的规则

- 移动同一个 `#chatPanel`，保持同一任务、草稿、引用、过程与提案状态。
- 中下区域不再保留第二个 Agent 面板或第二个输入框。
- 右侧以“Agent / 节点详情”切换当前占用空间；这是唯一面板的位置变化，不是新增一个助手。
- 返回底部时恢复默认职责：Agent 回中下区域，右栏显示节点详情。
- 无需创建第二套任务存储、接口或资料管理状态。

## 7. 视觉规格

延续现有白色面板、冷灰底与蓝灰强调色，颜色使用 `--panel`、`--surface-2`、`--panel-border`、`--text`、`--muted`、`--accent`，同时兼容深色与自定义强调色。

- 标题 16–18px，页签与正文 14px，辅助信息 12px。
- 右栏横向内边距 18–20px；控件间距 8px，区块间距 16px。
- 常用 UI 使用 Microsoft YaHei UI / PingFang SC，小说内容可沿用宋体。
- 使用统一的 16px 线条图标，点击区域至少 32px；边框以分隔内容为主，减少嵌套卡片。
- 内容、属性、Agent 停靠切换使用短过渡，尊重减少动态效果设置。

## 8. 实施顺序

| 阶段 | 交付 | 涉及文件 |
| --- | --- | --- |
| 第一批 | 右栏内容优先、内容/属性组织、标题及操作精简 | `app.js`、`index.html`、`canvas_theme.css` |
| 第二批 | 中下 Agent 标题、输入区、资料与修改列表视觉优化 | `chat_workspace.js`、`chat_workspace.css`、`index.html` |
| 第三批 | 停靠切换、单一面板约束、草稿保留与窄窗口行为验证 | `app.js`、`chat_workspace.js` |

继续采用原生 JS/CSS，复用现有任务系统和受控提案 API。现有代码已支持单面板移动，实施时主要完善外壳和状态处理。

## 9. 验收标准

- 任意布局只能看到一个 Agent 工作区和一个 Agent 输入框。
- 底部停靠时，右栏展示节点详情；切右侧停靠时，底部 Agent 消失。
- 1440×900、1280×720 和窄窗口下，标题操作无重叠、输入和停止按钮可见，中央内容可用。
- 切换停靠、任务、页签时恢复各自草稿和状态；流式新回复不抢历史阅读位置。
- 节点编辑草稿不会因添加引用或展开 Agent 丢失。
- 属性保存、内容保存、提案审阅走各自现有受控 API，接受修改仍需现有差异审阅操作。
- 浅色、深色、自定义强调色下，文字、选中态和键盘焦点清楚可辨。
- 使用隔离的合成小说和模拟 AI 做必要回归，不直接修改真实小说测试。
